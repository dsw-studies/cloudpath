Алгоритмы поиска, разделяй-и-властвуй и сортировка

Конспект объединяет две полученные части записи. Польские формулировки преподавателя местами распознаны неточно, поэтому обозначения и псевдокод приведены в стандартном виде.

1. Главная идея лекции / Główna idea

RU. Алгоритм нужно оценивать не только по математической красоте, но и по корректности реализации, ограничениям компьютера и объёму входных данных. Для маленьких массивов простой алгоритм часто безопаснее: его легче проверить и в нём меньше ошибок. Для больших массивов выигрыш от правильной асимптотики становится огромным.

PL. Algorytm oceniamy także przez poprawność implementacji, ograniczenia komputera i rozmiar danych. Dla małych danych prostsze rozwiązanie bywa lepsze, a dla dużych decyduje złożoność.

2. Линейный и бинарный поиск

Линейный поиск проверяет элементы один за другим. В худшем случае он делает n сравнений.

Бинарный поиск работает только в отсортированном массиве: на каждом шаге отбрасывается половина диапазона.

Tlinear(n)=O(n),    Tbinary(n)=O(log2n)
left = 0; right = n - 1
while left <= right:
    mid = left + (right - left) // 2
    if a[mid] == x: return mid
    if a[mid] < x: left = mid + 1
    else: right = mid - 1
return не найдено

Важно: проверка середины и выбор правильной половины должны быть согласованы. Ошибка в знаке сравнения или границе диапазона даёт неправильный результат или бесконечный цикл.

3. Поиск минимума и максимума

Для минимума начальное значение берём из первого элемента. Для каждого следующего элемента сравниваем его с текущим минимумом:

min = a[0]
for i = 1 … n-1:
    if a[i] < min:
        min = a[i]

Частая ошибка — поставить условие min > a[i] наоборот или сравнивать не с текущим минимумом. Сравнение выполняется почти всегда, а присваивание — только при улучшении результата.

Линейный просмотр
Минимум: до n−1 сравнений.
Максимум: до n−1 сравнений.
Попарный метод
Сравниваем элементы парами, меньший отправляем кандидатам минимума, больший — кандидатам максимума.

4. Принцип «разделяй и властвуй»

Задача разбивается на меньшие подзадачи. К каждой применяется тот же алгоритм, затем результаты объединяются. Это особенно естественно вместе с рекурсией.

T(n)=2T(n/2)+O(n)  ⇒  T(n)=O(n log n)

Базовый случай рекурсии: массив длины 0 или 1 уже отсортирован.

5. Сортировка слиянием / Merge sort

  1. Разделить массив на две части.
  2. Рекурсивно отсортировать обе части.
  3. Слить два отсортированных массива, каждый раз выбирая меньший первый элемент.
mergeSort(A):
    if length(A) <= 1: return A
    B, C = split(A)
    return merge(mergeSort(B), mergeSort(C))

При стабильном слиянии, если элементы равны, сначала берётся элемент из левой части. Так сохраняется исходный порядок равных элементов.

6. Быстрая сортировка / Quick sort

Выбирается опорный элемент (pivot), после чего массив разделяется на элементы, меньшие или равные pivot, и элементы, большие pivot. Выбор pivot влияет на скорость.

Средний случай: O(n log n)  ·  худший случай: O(n²)

Если каждый раз выбирать самый маленький или самый большой элемент, разбиение получается неравномерным и рекурсия становится глубокой. Случайный или медианный pivot обычно надёжнее.

7. Стабильность сортировки

Сортировка стабильна, если равные ключи сохраняют взаимный порядок. Сортировка выбором обычно нестабильна: обмен найденного минимума с первым элементом может перескочить через равный элемент.

Пример: обозначим равные ключи как 2ₐ и 2ᵦ. Если до сортировки порядок 2ₐ, 2ᵦ, нестабильный обмен может дать 2ᵦ, 2ₐ.

8. Что проверить в своей реализации

  • пустой массив и массив из одного элемента;
  • уже отсортированный и обратно отсортированный массив;
  • повторяющиеся элементы;
  • чётное и нечётное количество элементов;
  • границы индексов и условие остановки рекурсии;
  • переполнение при вычислении середины: использовать left + (right-left)//2.

9. Размер входных данных и сложность

Размер данных — это не только длина массива. В разных задачах им может быть число элементов, вершин или рёбер графа, размер матрицы и т. п. Время работы алгоритма рассматривается как функция размера входа n, обычно в худшем случае.

T(n) — число элементарных операций; нас интересует скорость роста T(n) при больших n

Константные множители и младшие слагаемые обычно не определяют класс роста: 3n+7 = O(n), 2n²+n+4 = O(n²), 0,1n log n+30n = O(n log n).

O(1)
константное время; не зависит от n.
O(log n)
каждый шаг уменьшает задачу, например бинарный поиск.
O(n)
один проход по данным.
O(n log n)
типичный класс эффективных сортировок.
O(n²)
двойной проход; часто простые сортировки.
O(2ⁿ)
экспоненциальный рост; быстро становится непрактичным.

10. Нотация Big‑O

Формально f(n)=O(g(n)), если существуют константы C>0 и n₀, такие что для всех n≥n₀ выполняется:

0 ≤ f(n) ≤ C · g(n)

Например, для f(n)=2n−1 можно взять C=2 и n₀=1, потому что 2n−1≤2n. Поэтому 2n−1=O(n).

Практический смысл: более быстрый компьютер не всегда компенсирует худший алгоритм. Алгоритм O(n²) на машине, которая в 1000 раз быстрее, всё равно может проиграть алгоритму O(n log n) на более медленной машине при достаточно большом n.

Краткая памятка / Ściąga

Поиск: линейный — O(n), бинарный — O(log n) и требует сортировки.
Merge sort: стабилен, O(n log n), требует дополнительной памяти.
Quick sort: обычно быстрый, но в худшем случае O(n²); важен pivot.
Разделяй и властвуй: меньшие подзадачи + объединение результата.
Главная проверка: корректность сравнений, границ и базового случая рекурсии.
