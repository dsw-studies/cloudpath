Функции: любое число параметров

  • Функция может принимать 0, 1 или много параметров. Параметры можно сделать необязательными (значение по умолчанию) или использовать *args и **kwargs.
  • *args — позиционные аргументы кортежем; **kwargs — именованные словарём (ключ — значение).
def f(*args, **kwargs):
    return args, kwargs

print(f(1, 2, a=3))   # ((1, 2), {"a": 3})

Большие числа: лимит int → str

  • Python считает сколько угодно большие целые, но превращение числа в строку (print, str) ограничено 4300 цифрами по умолчанию — защита от зависаний.
  • Снять/поднять лимит: sys.set_int_max_str_digits(n); 0 = без лимита (тогда ограничена только память).
  • Преподаватель показывал в Google Colab факториал в цикле: память росла до перегрузки — на своём компьютере так можно «повесить» систему. Пробуй большие вычисления в Colab.
  • Если памяти не хватает — можно держать данные в файле и работать с ними как с массивами numpy (медленнее, зависит от диска).
  • Для длинных циклов: clear_output (Colab/Jupyter) и прогресс-бар (например, tqdm) вместо тысяч строк в консоли.
import sys, math
sys.set_int_max_str_digits(0)      # 0 = без лимита
print(len(str(math.factorial(3000))))   # 9131 цифр

Процессы и потоки

  • Процесс стоит выше: при создании у него всегда один главный поток; в процессе можно запускать ещё потоки.
  • Один Python-процесс по умолчанию считает на одном ядре. Чтобы ускорить тяжёлые вычисления, разбивают данные на части и считают параллельно.
  • Если потоков больше, чем ядер, процессор переключается между ними — это не настоящий параллелизм. Операционная система сама решает, сколько ресурсов дать приложению.
  • Порядок выполнения потоков не контролируем; надо дождаться окончания всех потоков, прежде чем показывать результат.
  • Готовые инструменты: concurrent.futures — ProcessPoolExecutor, ThreadPoolExecutor, а также multiprocessing.Pool (метод map): задачи кладёшь в пул, он сам распределяет работу.
from concurrent.futures import ProcessPoolExecutor

def work(n):
    return n * n

if __name__ == "__main__":      # обязательно на Windows
    with ProcessPoolExecutor() as ex:
        print(list(ex.map(work, range(5))))   # [0, 1, 4, 9, 16]

От меня: у потоков в CPython есть GIL — вычисления на нескольких потоках почти не ускоряются, для тяжёлой арифметики берут процессы. Строка if __name__ == "__main__" нужна на Windows, иначе код пула запустится в каждом процессе заново.

Запись в один файл из нескольких потоков

  • Один файл можно открыть в нескольких программах, но сохранить изменения сможет не всякая: пока одна держит файл, остальные получат ошибку (файл заблокирован). Word поэтому создаёт временный файл-замок рядом с документом.
  • В многопоточной программе так же нужен замок (Lock): поток записал, освободил — следующий записывает. Иначе файл можно испортить.
import threading
lock = threading.Lock()

def save(line):
    with lock:                       # одновременно пишет один поток
        with open("out.txt", "a") as f:
            f.write(line + "\n")
6

Зачем нужны классы (ООП)

  • Код пишут сначала процедурно, потом при рефакторинге повторы выносят в функции; когда функций много — группируют в модули и классы.
  • Пример: сайт с меню, подвалом, карточками. Каждый элемент — класс со своими функциями (сортировка, ссылки, запросы к API).
  • Плюсы: многократное использование, понятная структура, функции сгруппированы в одном месте, часть данных можно скрыть от пользователя.
  • Если у части кода одна-две функции — класс не нужен; проект может быть смешанным.
  • Чистый код: функция должна делать одну задачу.

Четыре кита ООП

ПонятиеСмысл
Инкапсуляцияданные и методы в одном объекте, внутренности скрыты
Абстракцияобобщение действий, шаблон класса
Наследованиеодин класс берёт всё у другого — меньше кода
Полиморфизмобъекты разной формы работают через общий интерфейс
  • Перегрузки методов в Python нет: если определить две функции с одним именем, работает последняя (в C++ — иначе).

Класс, объект, __init__, self

  • Имя класса — с большой буквы; после заголовка и после каждого def — двоеточие.
  • Объект имеет свойства (данные), поведение (методы), состояние и идентичность (свой id).
  • __init__ — конструктор (dunder-метод, «двойные подчёркивания»); выполняется один раз при создании объекта.
  • Каждый метод получает self первым параметром; без него метод не видит данные объекта. К полям: self.name.
  • Тип объекта — просто имя класса (int, str — тоже классы).
  • Два объекта с одинаковыми данными не равны (== сравнивает адреса), пока не определишь __eq__.
class Person:
    def __init__(self, name="", surname="", age=0):
        self._name = name
        self._surname = surname
        self._age = age

    def get_name(self):            # getter
        return self._name

    def __str__(self):             # для print
        return f"{self._name} {self._surname} {self._age}"

    def __repr__(self):            # для разработчика
        return f"Person({self._name!r}, {self._surname!r}, {self._age})"

    def __eq__(self, other):
        return (self._name, self._surname, self._age) == \
               (other._name, other._surname, other._age)

    def __del__(self):             # деструктор
        print("usunieto osobe")

p1 = Person("Jan", "Kowalski", 18)
p2 = Person("Jan", "Kowalski", 18)
print(p1)             # Jan Kowalski 18
print(p1 == p2)       # True  (благодаря __eq__)
print(p1 is p2)       # False (разные объекты)
print(type(p1).__name__)   # Person
  • __str__ нужен, чтобы print(obj) показывал данные, а не «object at 0x…». В Django он же нужен, чтобы в админке в списках были имена.
  • __repr__ — однозначное представление для разработчика; используется в отладке, в f-строке с !r и как запасной вариант, если __str__ нет.
  • __del__ вызывается при удалении объекта: можно сохранить данные в файл/БД, освободить ресурс.

Начальные значения переменных

  • Переменную полезно сразу задавать значением (0, пустая строка, []): так видно, отработал ли код.
  • Классический пример — сумма: suma = 0 перед циклом.
suma = 0
for i in range(10):
    suma += i
print(suma)    # 45

От меня: в Python необъявленная переменная даёт ошибку (NameError), «мусор из памяти», как в C, не появляется. Но привычка задавать начальные значения остаётся хорошей.

Наследование и super()

  • class Student(Person): — студент получает всё, что есть у Person (поля, методы, __str__, __repr__, __del__).
  • Если у дочернего класса свой __init__, нужно вызвать конструктор родителя: super().__init__(...) и добавить свои поля.
  • super().__str__() берёт строку родителя, и можно только дополнить её.
  • Если ничего не меняешь — достаточно class Teacher(Person): pass.
class Student(Person):
    def __init__(self, name, surname, age, index):
        super().__init__(name, surname, age)
        self.__index = index           # свой дополнительный атрибут

    def __str__(self):
        return super().__str__() + f" [{self.__index}]"

s = Student("Anna", "Nowak", 19, 12345)
print(s)                          # Anna Nowak 19 [12345]
print(isinstance(s, Person))      # True

Поправка к паре: преподаватель сказал, что в Python можно наследоваться только от одного класса. Это не так: Python поддерживает множественное наследование (class C(A, B):). Просто на курсе его пока не разбирают.

Пример: прямоугольник и квадрат

  • Квадрат — частный случай прямоугольника: передаём одну сторону дважды в конструктор родителя.
  • Методы area и perimeter наследуются без изменений; переписываем только __init__ и __str__.
class Rect:
    def __init__(self, a=0, b=0):
        self._a = a
        self._b = b
    def area(self):      return self._a * self._b
    def perimeter(self): return 2 * (self._a + self._b)

class Square(Rect):
    def __init__(self, a):
        super().__init__(a, a)
    def __str__(self):
        return f"Square: area={self.area()}, perimeter={self.perimeter()}"

print(Square(10))   # Square: area=100, perimeter=40

Инкапсуляция: public / protected / private, property

ВидЗаписьСмысл
publicnameдоступно всем
protected_nameвнутри класса и наследников (по соглашению)
private__nameвнутри класса; Python меняет имя на _Класс__name
  • Это защита от случайного доступа, не от взлома: до скрытого поля всё равно можно добраться (например, s._Student__index).
  • Getter/setter: даём доступ к полю только через методы, где можно проверить значение.
  • Удобнее через @property: выглядит как обычное поле, а проверка внутри.
class Temp:
    def __init__(self):
        self._c = 0
    @property
    def c(self):
        return self._c
    @c.setter
    def c(self, v):
        if v < -273.15:
            raise ValueError("below absolute zero")
        self._c = v

t = Temp()
t.c = 25
print(t.c)        # 25
t.c = -300        # ValueError

Объекты внутри объектов

  • В поле класса можно хранить числа, строки, списки, словари и другие объекты. Например, класс со списком людей: self._persons = [], метод add(person) делает append.
  • Список создаём в __init__ (для каждого объекта свой).
class People:
    def __init__(self):
        self._persons = []
    def add(self, person: Person):
        self._persons.append(person)
    def __str__(self):
        return "\n".join(str(p) for p in self._persons)

ppl = People()
ppl.add(Person("Jan", "Kowalski", 18))
ppl.add(Person("Ewa", "Nowak", 181))
print(ppl)

Абстрактные классы, classmethod, staticmethod

  • Абстрактный класс — шаблон: описывает, какие методы должны быть у потомков, но не реализует их. Создаётся из ABC с декоратором @abstractmethod. Создать объект такого класса нельзя.
  • @staticmethod — функция внутри класса, не связана с объектом и с self; вызывается по имени класса.
  • @classmethod — получает cls (сам класс), а не self; работает с данными класса.
from abc import ABC, abstractmethod

class Shape(ABC):
    @abstractmethod
    def area(self): ...

Shape()   # TypeError: нельзя создать объект абстрактного класса

class S:
    count = 0
    @classmethod
    def inc(cls):
        cls.count += 1
        return cls.count
    @staticmethod
    def hello():
        return "hi"

print(S.inc(), S.hello())   # 1 hi

Шпаргалка

  • Класс — с большой буквы, : после заголовков, self в каждом методе.
  • __init__ → поля; __str__ → print; __repr__ → отладка; __eq__ → сравнение; __del__ → удаление.
  • Наследование: class B(A): + super().__init__(...).
  • Скрытие: _x (protected), __x (private); доступ — через getter/setter или @property.
  • Перегрузки нет — последняя функция с этим именем побеждает.
  • Абстракция: ABC + @abstractmethod; @staticmethod, @classmethod.
  • Процессы/потоки: ProcessPoolExecutor, Lock на общий файл, if __name__ == "__main__".
  • Лимит int → str: sys.set_int_max_str_digits(0).
